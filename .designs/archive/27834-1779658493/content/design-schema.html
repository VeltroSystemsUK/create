📐 Design Section 1/5: Content Schema System

How the CMS knows what content exists and how it's structured.

The Core Idea

Every block in Framework Builder has props — headline, subtext, imageUrl, bg, etc. The CMS generates a content schema by scanning all blocks across all pages and identifying which props are "content" vs "design."

Auto-Detection Rules

✅ Editable (content)
  • Props named: headline, title, text, subtext, body, description, caption, quote
  • Props named: imageUrl, videoUrl, avatarUrl, logoUrl
  • Props named: name, label, btnText, ctaText
  • Props that are strings/arrays of strings (heuristic)
🔒 Locked (design)
  • Props named: bg, textColor, accentColor, saleColor
  • Props named: paddingV, paddingH, gap, columns, imageHeight
  • Boolean/color/number props (heuristic)

Schema Format (JSON)

{
"pages": [
  {
    "pageId": "p_abc12",
    "name": "Home",
    "slug": "index",
    "blocks": [
      {
        "blockId": "b_xyz99",
        "type": "hero",
        "fields": {
          "headline": { "editable": true, "type": "string" },
          "subtext": { "editable": true, "type": "richtext" },
          "ctaText": { "editable": true, "type": "string" },
          "bg": { "editable": false, "type": "color" }
        }
      }
    ]
  }
]
}

Manual Override

In the builder's right panel, each auto-detected prop shows a small lock/unlock icon. Click to toggle. Developer can also mark array fields (like team members, FAQ items, pricing plans) as editable content collections.

This generates a cms-schema.json that maps every editable field on every page. The schema is what drives both the admin dashboard forms and the inline editing.
