🔌 Design Section 5/5: API Layer & Export

The backend endpoints and how the CMS gets wired into exported sites.

CMS API Endpoints (in server.py)

GET /api/cms/schema → Return the content schema for this site
GET /api/cms/content → Return all current content values
PUT /api/cms/content → Update a single field value
PUT /api/cms/content/bulk → Update multiple fields at once (form save)
POST /api/cms/media/upload → Upload a new image to /media
GET /api/cms/media → List all uploaded media
DELETE /api/cms/media/{id} → Delete an uploaded image
POST /api/cms/auth/login → Authenticate (password → session token)
POST /api/cms/auth/check → Verify session is still valid

Data Storage

📄 cms-schema.json
Auto-generated on export. Maps every editable field across all pages. Read-only for the CMS (used to render forms and validate edits).
📄 cms-content.json
Stores the actual content values. The CMS reads from this to serve content, and writes to it when the client saves edits. Lives alongside the exported site.
📄 cms-config.json
Admin password hash, site title, and other settings. Created on first login.
📁 /media/
Uploaded images stored here. Referenced by filename in cms-content.json.

Export Structure

When you click "Export with CMS", the generated site folder looks like:

my-site/
├── index.html ← Home page (static HTML)
├── about.html ← Other pages
├── services.html
├── css/ ← Site styles (copied from builder)
├── js/ ← Site scripts + cms-edit.js
├── cms-schema.json ← Auto-generated content map
├── cms-content.json ← Current content values
├── cms-config.json ← Password hash, settings
├── media/ ← Uploaded images
├── admin.html ← Admin dashboard (SPA)
└── cms-server.py ← Lightweight CMS server (or served by main server)

How Content Flows

1. Site loads → HTML has placeholder content from export
2. cms-edit.js runs → fetches content from /api/cms/content
3. JavaScript replaces placeholder text with actual CMS content
4. Client edits → inline or via /admin → API writes to cms-content.json
5. Next page load → updated content is served immediately

For static hosting (no Python server), an alternative: rebuild the HTML files with baked-in content on each save ("static mode").
