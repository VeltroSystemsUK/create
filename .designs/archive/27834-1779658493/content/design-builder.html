🔧 Design Section 2/5: Builder Integration

What the developer sees in Framework Builder to set up the CMS.

CMS Panel in the Builder

A new "CMS" tab in the left panel (alongside Blocks, Pages, Design, etc.) with these sub-sections:

🔑
Access Control
Set a client password (or magic link) for the admin dashboard. Client email for notifications.
🏷️
Content Map
Shows all pages with their editable fields. Toggle fields on/off. Rename field labels for clients ("Hero Headline" → "Main Title").
🖼️
Media Library
Manage uploaded images. Clients can browse and select from their media library when editing.
📤
Export with CMS
Export button generates the site with CMS wiring — schema, API endpoints, admin panel, inline editing script all included.

Per-Prop Override UI

In the right panel when a block is selected, each prop shows a small CMS toggle. It blends right into the existing property editor.

Default state follows auto-detection. Developer unchecks to lock, checks to expose. Field labels can be customised for the client's admin panel.

Does this builder integration design look right? The key idea: CMS setup is a new tab in the left panel, plus per-prop toggles in the right panel that feel native to the existing UI.
