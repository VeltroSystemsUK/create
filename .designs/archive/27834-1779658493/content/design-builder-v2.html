🔧 Design Section 2/5: Builder Integration (Revised)

Zero CMS setup in the builder. It just works on export.

The Revised Approach

There is no CMS tab, no CMS panel, no per-prop toggles in the builder. You build your site exactly as you do today — drag blocks, set props, arrange pages. The CMS is entirely about the exported live site.

How It Works

1️⃣
Build as normal
Use Framework Builder as you always do. No CMS-specific steps.
2️⃣
Export with CMS
Click "Export with CMS". The system auto-scans all blocks/pages, generates the content schema, and bundles the CMS server + admin panel with the exported site.
3️⃣
Deploy to client
The exported site includes everything needed: the site HTML, a lightweight CMS server (cms.py), the admin dashboard, and the inline editing script.
4️⃣
Client edits content
Client visits their site → inline edit clicks or /admin dashboard. No Framework Builder involved at all.

Only Configuration Needed

On first run of the exported site, the CMS prompts for:

  • Admin password — set once, used to access /admin
  • That's it. Everything else is auto-configured from the build.

Does this revised approach feel right? No CMS in the builder — the CMS is just what ships with the exported site.
