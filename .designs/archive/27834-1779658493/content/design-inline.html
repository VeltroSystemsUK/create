✏️ Design Section 4/5: Inline Editing

Click-to-edit on the live site — the quickest way for clients to make changes.

How It Works

🔐
Enter Edit Mode
Client visits their site and appends ?edit to the URL (or clicks a small pencil icon in the corner). Enters their password. Site enters edit mode.
👆
Click to Edit
Editable elements get a subtle dashed border on hover. Click any text or image to edit it inline. Text becomes an input/textarea. Images open a picker or upload dialog.
💾
Auto-Save
Changes save as the client works (debounced). A small "Saved" indicator appears. No manual save button needed for inline edits.
🚪
Exit Edit Mode
Click "Done Editing" to exit. The site returns to visitor mode. Changes are live.

Technical Approach

A small JavaScript file (cms-edit.js) is included in the exported site. When ?edit is detected and the client is authenticated:

  • Loads the content schema to know which elements are editable
  • Adds contenteditable to text elements and click handlers to images
  • On change, sends the updated value to the CMS API (/api/cms/content)
  • The server stores the new value in the content JSON file
  • Subsequent page loads serve the updated content

What Gets Highlighted

✅ Editable on click
  • Headlines, titles, text blocks
  • Button labels, CTA text
  • Images (click to replace)
  • List items (add/remove/reorder)
  • Rich text areas
🔒 Not editable inline
  • Background colors, spacings
  • Layout structure, columns
  • Block order, page structure
  • Font styles, sizes

Does this inline editing design feel right? The key idea: client appends ?edit to their URL → clicks to edit → auto-saves → exits.
