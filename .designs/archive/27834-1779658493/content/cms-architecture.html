🏗️ CMS Architecture — Where does the backend live?

The CMS needs a server for APIs. Three approaches:

A

Extend server.py

Add CMS API routes to the existing Python dev server. When you export a site, it includes a lightweight CMS server. Single codebase, one port, one deployment.

Simple deployment One codebase Matches existing pattern
B

Standalone CMS Server

A separate cms.py on its own port. Clean separation from the builder. Can serve content to multiple live sites from one instance. More complex but more scalable.

Multi-site Clean separation Scalable
C

File-Based + Admin Panel

Content stored as JSON files alongside the exported site. The admin panel edits files directly via the browser — no separate server needed for the live site. Simplest possible deployment: just static files.

No server needed Static deploy Dead simple

I recommend A (Extend server.py) — keeps things simple, matches your existing architecture, and the Python server is already handling API endpoints.
