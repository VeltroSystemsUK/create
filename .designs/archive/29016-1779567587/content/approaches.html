Three approaches to the Design Studio

Pick the one that feels right — I've marked my recommendation.

A

Fabric.js — Recommended ★

Fabric is the library most Canva-like tools are built on. One CDN script gives you: object selection & transforms, rich text editing, image placement, JSON save/load, PNG and SVG export, and a canvas object model that maps directly to your feature list. The UI around it (layers panel, align toolbar, template picker, AI panel) is custom-built to match your existing dark theme.

Pros

  • Ships 90% of the hard canvas math already solved
  • JSON serialization = free save/load
  • toDataURL → PNG, toSVG → SVG — one line each
  • 380KB CDN, no build step
  • Massive community, tons of patterns for Canva-clones

Cons

  • Layers panel, align UI, template picker all need custom code
  • ~380KB added to page weight
B

Konva.js

Stage/Layer/Shape model — excellent performance with many objects on screen. Similar CDN story to Fabric. More suited to interactive apps than design tools, so more boilerplate is needed to replicate Canva-style selection handles and text editing.

Pros

  • Better raw performance at high object counts
  • Clean, predictable API

Cons

  • Less "design-tool-native" — selection handles, text editing, image filters all need more manual work than Fabric
  • Smaller ecosystem for this specific use case
C

Custom SVG editor (no library)

Build the editor from scratch using SVG DOM APIs. Full control, zero weight. But selection handles, transforms, text editing, image embedding, and undo/redo all have to be written manually — this is months of work, not weeks.

Pros

  • Zero dependencies, complete control
  • Pure SVG output (most scalable format)

Cons

  • Enormous implementation effort
  • Reinventing solved problems
